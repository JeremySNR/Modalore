# Codex integration research

Checked 4 November 2026. The [Codex app-server protocol](https://learn.chatgpt.com/docs/app-server) documents newline-delimited local stdio, initialization, account and model discovery, threaded turns, progress notifications, approval requests and interruption. The installed Windows executable reports `codex-cli 0.166.0-alpha.6` and marks app-server experimental. Its `generate-ts` schema was inspected locally. Protocol compatibility should be checked against each supported release; no minimum stable version is asserted yet.

The [platform guide](https://developers.openai.com/blog/codex-as-a-platform) positions app-server for an agent embedded in a product, the SDK for programmatic workflows, and `codex exec` for bounded scripts. The desktop adapter uses a private stdio child and leaves authentication in Codex; it does not call a model API or read credential files. `account/login/start` provides Codex-managed browser sign-in. The model catalog is not proof of entitlement. Account limits apply; no balances are inferred. OpenAI also describes a separate [Sign in with ChatGPT preview for open-source projects](https://developers.openai.com/siwc/token-sharing-open-source); its eligibility and requirements must be reviewed before release or any hosted/commercial distribution. The present local Codex-managed flow is not a claim of approval for a future hosted service.

The adapter asks for workspace-write with network disabled and on-request approval; unexpected server requests fail closed and file/command approvals default to decline. A caller can present the exact request to a user and accept that single action. Actual operating-system sandbox enforcement depends on Codex and platform configuration, so this is not proof that arbitrary generated code is safe. Installation and artifact validation remain separate application responsibilities. The process inherits the user's Codex configuration and does not modify it. No raw protocol or stderr is logged.

Local probe: the installed CLI reported a ChatGPT sign-in. With normal local state access, initialization, account read and model discovery succeeded (eight catalog entries). A real model turn streamed item events. Its file edit requested approval, which was first declined; the turn nevertheless ended `completed` without writing an artifact, so completion alone is not artifact validation. A second probe explicitly approved only the named test JSON file patch, creating `{ "greeting": "hello" }` and revising it to `{ "greeting": "welcome" }` in the same thread. A separate turn returned `interrupted` after cancellation. The approval reason was “command failed; retry without sandbox?”; this verifies an approved patch, not sandbox enforcement. The managed development sandbox also denied app-server state initialization without additional runtime access. Windows sandbox behavior and onboarding need testing on a clean end-user installation.

An opt-in reproducible integration probe is available as `npx tsx scripts/probe-codex.ts`. On 4 November 2026, with the installed CLI and its configured default model, it created a real recipe using the current schema (`enemyHealthMultiplier` included), validated it, and installed it as a version in an isolated profile. A follow-up changed only `coinMultiplier` from 1 to 2; the revised recipe passed validation, was exported with its parent hash, imported, and installed in a second clean profile with the same recipe hash. An interrupted third turn left both installed profile pointers unchanged. The probe approved only file-change requests naming its exact workspace recipe, and declined commands, unknown paths, and broader grants. This demonstrates recipe schema, version and package integrity, not a compiled mod, game launch or observed gameplay. The probe required normal Codex state access outside the managed workspace sandbox. As with the earlier probe, explicit patch approval does not establish native Windows sandbox enforcement.

For Windows npm installs, the adapter resolves `codex.cmd` to the native optional-dependency binary instead of running a batch file through a shell. The [OpenAI Codex launcher](https://github.com/openai/codex/blob/main/codex-cli/bin/codex.js) and [SDK resolver](https://github.com/openai/codex/blob/main/sdk/typescript/src/exec.ts) establish the current and legacy package layouts. Temporary fixtures test nested and hoisted local npm layouts. An isolated npm installation of `@openai/codex` 0.166.0 was resolved from its local `.bin` shim to the actual Windows native executable; `--version`, app-server initialization and read-only account status succeeded with normal Codex state access. This verifies the installed distribution, not first-run onboarding on a clean Windows machine.
